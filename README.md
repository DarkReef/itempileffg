# ItemPileFFG 0.2.0

Отдельный модуль инвентаря и торговли для Apex Heresy, Foundry VTT 14. Для торговли и передачи между персонажами используются Item Piles 3.x, libWrapper и socketlib. Обычный инвентарь, перемещение внутри персонажа и шаблоны не вызывают Item Piles.

## Установка

Манифест последнего опубликованного релиза:
https://github.com/DarkReef/itempileffg/releases/latest/download/module.json

Версия 0.2.0 в этой ветке ещё не опубликована. Система устанавливается отдельно. Для нового отображения оставшихся ран нужен PR системы 1.5.4.

## Рюкзак — обычный предмет

Создайте обычное снаряжение в «Предметах» или разблокированном компендиуме. Откройте лист, включите «Предмет является контейнером», задайте собственный вес, цену и вместимость. 0 кг вместимости означает отсутствие ограничения; количество контейнера должно быть 1.

В раздел «Содержимое» перетащите предметы мира или компендиума. Можно вкладывать другие контейнеры-шаблоны, редактировать количества и удалять предмет вместе с его вложениями. Удаление из шаблона не удаляет исходные предметы мира. Цена внешней сумки остаётся заданной пользователем, стоимость вложений её автоматически не заменяет.

Перетащите шаблон на лист персонажа либо на уже существующий рюкзак. Создаётся независимое дерево с новыми ID. Количество, вес, цена, эффекты и прочие исходные данные сохраняются; вложенные вещи становятся неэкипированными. Изменения шаблона не затрагивают выданные копии.

## Вкладка снаряжения

- Стрелка на строке раскрывает контейнер. В строке видны вес содержимого и вместимость, в подсказке — собственный и полный вес. Штатные открытие, чат и удаление сохранены.
- Предмет на рюкзак: поместить внутрь. Рюкзак на рюкзак: вложить. Верхняя пунктирная зона: вынуть в корень. Перемещение внутрь снимает экипировку; извлечение не надевает вещь автоматически.
- Подсветка зелёная для допустимой цели, красная для ошибочной. Циклы и превышение вместимости предков отклоняются.
- Кнопки ↳, ↥ и ⚙ — резервные действия «Поместить», «Вынуть» и «Открыть/настроить». Окно «Рюкзаки и торговля» осталось дополнительным интерфейсом.
- Раскрытие хранится только в клиентской памяти и не обновляет Actor.

## Передача и торговля

Между управляемыми персонажами перенос идёт через Item Piles и включает потомков контейнера. Перенос в контейнер назначения повторно проверяется перед фиксацией транзакции на стороне Item Piles. Для передачи чужому персонажу используйте штатный диалог «Передать» с согласием получателя.

Наполненный контейнер продаётся одним набором за цену корня: его содержимое не оплачивается повторно. Бесконечный запас торговца сохраняется. Штатные обработчики Item Piles обслуживают передачу персонажам, торговцам и добыче на сцене. Междокументные транзакции Item Piles не являются атомарной транзакцией базы данных; их поведение при сетевом сбое требует живого QA.

## Валюта

Настройки модуля задают название и значок валюты (по умолчанию «Троны»); суммы хранятся в `system.economy.credits`. Мастер может редактировать кошелёк, создавать валюту на карте и превращать выбранные токены в торговцев. При запуске исправляются пустые стандартные настройки экономики Item Piles; пользовательские адаптеры валют не заменяются.

## Данные и совместимость

Поля `system.quantity`, `system.price` и `system.inventory.*` сохранены. Единственная служба `scripts/container-service.mjs` объединяет проверку/перемещение, сериализацию, создание копий и транзакции; существующие `descendants`, `movePatch`, `contentsMass`, `remapContainers` переиспользуются. Торговля и шаблоны используют один механизм копирования дерева.

Содержимое предмета-шаблона хранится в `flags.itempileffg.containerTemplate = {version:1, items:[root,...descendants]}`. Корень всегда берётся из текущего Item; сохранённые ID служат только внутренними ссылками снимка. Старый `flags.itempileffg.kit` читается без удаления. Старые API `saveContainerKit` и `grantKit` оставлены для макросов, но отдельных сущностей и кнопок комплектов больше нет.

Разрушающих миграций нет. Неизвестные версии снимков отклоняются. Предметы с отсутствующим родителем показываются в корне; циклы не обрушивают лист. Вся вместимость проверяется до создания дерева. При частичной ошибке создания удаляются только ID текущей операции; при отказе сервера в откате требуется ручная проверка журнала.

## Проверки

`npm test` — автоматические тесты. Полный живой smoke test Foundry VTT 14 (GM/игрок, сцена, торговец, компендиум, синтетический Actor) ещё требуется; браузерный стенд использует реальные шаблоны/код и имитацию документов. Полный вес складывается по физическим предметам один раз, с учётом количества, включая нулевые стопки.
